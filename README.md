# selfsni-centos

Bash-скрипт для настройки на CentOS одностраничного сайта, который может служить HTTPS-целью для REALITY. Страница посвящена одному из пяти героев Dota 2.

## Перед запуском

- Нужен сервер CentOS с `dnf` и правами root.
- A-запись домена должна указывать на публичный IPv4 сервера.
- Порт 80 должен быть доступен извне для проверки домена Let's Encrypt. Порт 443 нужен для отдельно настроенного входящего сервиса REALITY.
- На сервере не должно быть конфликтующих конфигураций nginx для этого домена и порта 80. Скрипт изменяет `/etc/nginx/conf.d/sni.conf` и `/var/www/html/index.html`.

## Запуск

```bash
sudo bash selfsni-centos.sh example.com 9000
```

Первый аргумент — домен. Второй — локальный HTTPS-порт nginx; если его не указывать, используется `9000`:

```bash
sudo bash selfsni-centos.sh example.com
```

Скрипт выводит имя выбранного героя и параметры, которые нужно перенести в конфигурацию REALITY:

```text
Target/Dest : 127.0.0.1:9000
SNI         : example.com
xver        : 1
```

## Откроется ли сайт по домену?

Да, если Xray слушает публичный порт `443` и в серверной конфигурации REALITY указаны `target` (или `dest`) = `127.0.0.1:9000`, `xver` = `1`, а `example.com` добавлен в `serverNames`. Остальные параметры VLESS/REALITY (UUID, ключи и т. д.) настраиваются отдельно. Обычный браузер передаст HTTPS-запрос через Xray в локальный nginx и увидит выбранную страницу.

Проверьте с другого устройства, без включённого VLESS-прокси: откройте `https://example.com` или выполните:

```bash
curl --noproxy '*' -I https://example.com
```

Ожидается ответ `200` без ошибки сертификата. Если HTTP перенаправляет на HTTPS, но страница не открывается, проверьте, что Xray слушает `443`, nginx — `127.0.0.1:9000`, а `target/dest`, `xver` и домен совпадают. Не добавляйте `-k` к `curl`: он скрывает ошибку сертификата.

## Что делает скрипт

1. Устанавливает nginx, Certbot и вспомогательные утилиты; запускает firewalld и добавляет правила для HTTP и TCP-порта 443.
2. Сравнивает A-запись домена с публичным IPv4 сервера. При несовпадении выводит предупреждение, но не останавливается.
3. Случайно выбирает одну из пяти встроенных страниц и записывает её в `/var/www/html/index.html`.
4. Создаёт временную конфигурацию nginx на порту 80. Если сертификата ещё нет, останавливает nginx и запрашивает сертификат Let's Encrypt через `certbot --standalone`.
5. Настраивает редирект с HTTP на HTTPS и HTTPS-сервер nginx на `127.0.0.1:9000` (или указанном порту) с `proxy_protocol`.
6. Проверяет конфигурацию nginx и перезапускает службу.

Сам скрипт **не устанавливает и не настраивает REALITY**. Он также не заставляет nginx слушать публичный порт 443: этот порт должен обслуживать отдельно настроенный входящий сервис, который передаёт соединение на локальный HTTPS-порт nginx с PROXY protocol версии 1. Локальный порт nginx открывать в firewalld не нужно.

## Автопродление сертификата

После первого успешного запуска основного скрипта установите ежедневную проверку для своего домена:

```bash
sudo bash setup-cert-renewal.sh example.com
```

Установщик добавит задание в `/etc/cron.d/selfsni-cert-renew-example_com`. Certbot запустится каждый день в 03:17 по времени сервера, но будет продлевать сертификат только ближе к окончанию его срока. На время продления nginx остановится, чтобы Certbot занял порт 80, а затем запустится снова и подхватит новый сертификат. Для успешного продления домен должен по-прежнему указывать на сервер, а порт 80 быть доступным извне.

Проверьте настройку после установки (тест на короткое время остановит nginx):

```bash
sudo certbot renew --dry-run --cert-name example.com \
  --pre-hook 'systemctl stop nginx' --post-hook 'systemctl start nginx'
```

Ошибки ежедневной проверки записываются в `/var/log/selfsni-cert-renew-example.com.log`. Повторный запуск установщика для того же домена обновит его cron-задание.

## Повторный запуск и проверка

Повторный запуск снова случайно выберет страницу и перезапишет `/var/www/html/index.html` и `/etc/nginx/conf.d/sni.conf`. Если сертификат для домена уже есть, повторно запрашивать его скрипт не будет.

Для проверки состояния на сервере:

```bash
nginx -t
ss -lntp
certbot certificates
```

Основной скрипт сам по себе не настраивает продление; для этого нужен отдельный установщик выше. Пакет Certbot также может содержать собственный таймер продления: он не заменяет проверку `--dry-run` с освобождением порта 80.
